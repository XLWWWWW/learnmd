# 05 · 答案与解析

建议先完成题册再阅读本页。完整可执行参考答案在 `solutions/e01.sh`～`e16.sh`；用 `./practice.sh solution E01` 验证单题，用 `./practice.sh solution` 验证全部。

## A. 理解题答案

### Q01

前两行输出 `<hello shell>`。第三行是执行名为 `name` 的命令，参数为 `=` 和 `world`；命令不存在时通常返回 127。赋值语法不能在等号两侧加空格。

### Q02

输出依次为 `<a>`、`<b>`、`<a b>`、`<$x>`。三次 printf 的数据参数数目分别是 2、1、1。第一处发生单词分割；双引号保留一个参数；单引号阻止变量展开。

### Q03

```text
count=3
<a b>
<>
<*.log>
[a b  *.log]
```

最后一行 b 与星号之间有两个空格，因为中间有一个空参数。`"$*"` 是一个连接后的参数；未引用 `$@` 会再次分割/匹配并丢失空参数，结果还依赖目录内容。

### Q04

第一行 `A|B`，第二行 `|B`。有冒号时，未设置和空串都使用默认值；没有冒号时只处理未设置。

### Q05

输出 `i=1 status=1`。后置自增表达式的值是自增前的 0，而算术命令把表达式 0 解释成失败状态 1；开启 `-e` 后在这个普通命令上下文中会提前退出。`08` 触发八进制数字错误，外部十进制输入应先校验再用 `10#`。

### Q06

依次为 0、1、0。未引用的 `api-*` 是 glob 模式；引用后星号是字面字符；`=~` 使用扩展正则，`[a-z]+` 表示至少一个小写字母。

### Q07

会打印 fallback。true 成功后执行 false，false 失败又触发 `||`。需要“只根据 a 决定分支”时，用明确的 if/else，不要让 b 的状态改变分支选择。

### Q08

先 child，再 parent。子进程的变量变化不会反向写回父进程。source 则在当前 Shell 中执行，会改变当前变量、目录和选项，甚至执行 exit 结束当前 Shell。

### Q09

`>result.txt 2>&1` 让两个流都去文件。`2>&1 >result.txt` 让 stderr 继续去原 stdout，只有 stdout 去文件。`>` 在命令执行前就可能创建/截断文件。

### Q10

依次为 0、1。pipefail 取管道中按位置最右边的非零状态，不是按时间最先或最后失败的命令。

### Q11

默认本题环境输出 0。循环在管道的子 Shell 环境里修改的是自己的变量。读取文件时把重定向放在循环之后：`while ...; do n=$((n+1)); done < file`。进程替换可保留循环作用域，但还需另行考虑生产者错误。

### Q12

原片段只输出 `<a>`。第二次 read 读到 last，但 EOF 前没有换行，返回非零，循环体没有进入。条件补为 `IFS= read -r line || [ -n "$line" ]`。IFS 和 -r 分别防止首尾分隔空白丢失及反斜杠解释。

### Q13

输出 `<a>`。命令替换去掉所有尾部换行，双引号只阻止后续分割/匹配，不能撤销这种去除。Bash 变量不能存 NUL，所以 NUL 文件清单和二进制应放在流或文件中。

### Q14

默认循环一次，打印 `<*.log>`。nullglob 开启后无匹配展开成零个参数，循环零次。普通 `*.log` 不匹配点开头的文件；需要明确 dotglob 或使用 find 等策略。

### Q15

字典排序为 10、2、2；数字排序为 2、2、10。直接 uniq -c 是三组各 1 次，因为两个 2 不相邻；先 sort 后 uniq -c 得到 10 一次、2 两次。uniq 输出的数字前可能带对齐空格，含义不受影响。

### Q16

这里 local 成功声明变量，因此函数最后命令的状态为 0，掩盖了 false。应拆成 `local value; value=$(false) || return`，让赋值命令的失败明确传播。

### Q17

```text
continued
reported-success
```

f 被用于 if 条件，errexit 在这种上下文中被忽略，函数内部 false 没使它退出；最后 printf 成功又让 f 返回 0。关键函数应自己检查内部步骤并 return，不能依赖调用者的 `-e`。

### Q18

source 会执行命令替换，stderr 出现 injected；APP_NAME 接收的是命令替换的 stdout（这里为空）。KEY=VALUE 右侧可以包含可执行语法，不代表这是纯数据。按明确协议解析数据，见 E09。

### Q19

打印 cleanup，最终保持状态 7。EXIT 是退出时执行的 trap 条件，不是外部信号。TERM 可以设置处理器，SIGKILL 无法捕获；处理器显式 exit 或错误地改写状态也可能改变最终状态，因此不要把清理函数写成无条件 exit 0。

### Q20

输出 7。`&` 启动异步工作时调用方尚不知道它最后能否成功；wait 获取这个子进程的终止状态。要汇总多项失败，保存每个 PID 并检查每个 wait。

### Q21

不能保证，existing.txt 可能已被截断。临时文件加发布避免失败写坏原内容；它不自动提供断电持久性、多个写者的冲突检测、原权限保留或不可信目录下的竞态防护。

### Q22

健康检查通常可安全重复；创建订单可能重复产生副作用，需要幂等键或服务端去重/事务保障。次数限制执行数量，单次超时限制一个请求的等待，总预算限制所有尝试和间隔合计的时间。

### Q23

都可能通过最初的“不存在”检查。第二个 mkdir 即使失败，原片段若继续执行也会进入 work。应该直接以 `mkdir` 成功为获得所有权的依据，失败即退出，只有成功者负责释放。

### Q24

不能假设可运行。declare -A、mapfile 是 Bash 版本问题；date -d、stat -c 是外部命令的 GNU/BSD 实现差异。换新版 Bash 不能自动让 macOS 的 date/stat 变成 GNU 版本。

## B. 排错题参考修复

### D01 · 文件遍历

不递归、只复制当前目录普通文件（片段，dir/backup 须为已校验路径）：

```bash
for file in "$dir"/*; do
    [ -f "$file" ] || continue
    cp -- "$file" "$backup/" || exit 1
done
```

这里普通 glob 不包括点文件，`-f` 还会跟随文件符号链接；按业务需求改用 find，或明确点文件/符号链接策略。需要递归时，用 find 生成 NUL 清单并保留相对目录结构；直接把所有文件复制进同一目录会发生重名冲突，不能仅替换遍历语法就声称实现了递归备份。E11 是归档方案。

### D02 · 数组

```bash
run() { "$@"; }
args=('hello world' '*.log')
run printf '%s\n' "${args[@]}"
```

数组保存两项；`"$args"` 只把整个旧字符串作为一项，无法重新找回设计中的边界。不要把参数先编码成依赖空格的字符串，再试图猜测拆分。

### D03 · 状态保存

```bash
if build; then
    printf 'built\n' >&2
else
    rc=$?
    printf 'build failed: %s\n' "$rc" >&2
    exit "$rc"
fi
```

`!` 已经把失败取反成成功，所以原来的 `$?` 可能为 0。build 函数内部也应逐步检查失败并 return，不能依赖它处在 if 条件时的 errexit。

### D04 · 先产出再发布

下面是工程根目录下的片段，settings.conf 由你在 scratch 准备：

```bash
tmp=$(mktemp "$PWD/scratch/.settings.XXXXXX") || exit 1
trap 'rm -f -- "$tmp"' EXIT
sed 's/old/new/g' scratch/settings.conf > "$tmp" || exit 1
./solutions/e10.sh scratch/settings.conf < "$tmp" || exit 1
```

不能只写 `sed ... | e10 target` 就承诺 sed 失败时目标不变，因为写入方只看见 EOF，不知道 sed 是否完成业务工作。先检查生成器成功再发布。此片段的 E10 将权限设为 0600；若要保留旧权限/属主，需要另加明确策略。

### D05 · 按阶段解释状态

```bash
# 此片段不启用 set -e；关键失败显式判断。
grep -F -e "$needle" < "$file" | LC_ALL=C sort -u
status=("${PIPESTATUS[@]}")
if [ "${status[0]}" -gt 1 ] || [ "${status[1]}" -ne 0 ]; then
    printf 'pipeline failed\n' >&2
    exit 1
fi
```

零匹配允许成功，错误不吞掉。若整份脚本已开启 errexit，应该在一个明确禁用该选项并管理状态的子 Shell/函数设计中处理这个管道，不能等自动退出以后再检查 PIPESTATUS。完整例子见 E16。

### D06 · 独有临时目录

```bash
umask 077
tmp=$(mktemp -d "${TMPDIR:-/tmp}/task.XXXXXX") || exit 1
trap 'rm -rf -- "$tmp"' EXIT
```

固定名字 `/tmp/task` 可能已有别人的数据。mkdir -p 对已存在目录也成功，不能证明所有权。mktemp 成功才注册清理，删除目标只来自该次创建结果。强杀后的残留需要独立恢复策略。

### D07 · 参数传递

```bash
grep -F -e "$keyword" < "$file"
```

字面值选 `-F`，`-e` 明确后面的值是模式，重定向避免文件名被当成选项。不经过 eval，关键词中的分号、命令替换等只是普通数据；若需要空结果成功，再按 E16 区分状态。

### D08 · 成功获取后才清理

```bash
mkdir -- "$lock" || exit 75
trap 'rmdir -- "$lock"' EXIT
run_job
```

这是所有权方面的最小修复；完整信号、子进程状态处理见 E14。原代码在获取失败退出时仍执行 trap，可能删掉其他进程拥有的空锁目录，破坏互斥。SIGKILL 不能触发正常清理，陈旧锁需要人工核实或其他锁机制。

### 三段值得自己写出来的正确性解释

**E10：** 写入只落在独有临时文件；cat 失败时根本不会执行发布；因此已有目标内容仍在。mv 在同目录的正常本地文件系统中发布完整新内容。该论证依赖可信目录、单写者和稳定目标类型，不能扩展成通用不可信目录的安全证明。

**E14：** 只有 mkdir 成功的进程能进入临界区；未获得锁的进程不运行任务且不删除锁。持有者在子任务退出后才删除自己的空目录。这个推理不覆盖 SIGKILL 后锁残留、锁目录被外部删除或网络文件系统差异。

**E15：** 只有当前批次未满时才启动任务；满 LIMIT 就逐一 wait，全部结束后才开启新批次，故同时运行的任务不会超过 LIMIT。失败只修改 failed 标志，不跳过剩余回收和任务；最后状态反映是否出现过失败。屏障测试验证真的并发，计数器测试验证上限和每项恰好一次。

## D. 综合项目参考设计

### P01 · 日志日报

分成“解析参数 → 生成独立临时报表 → 校验/筛选/格式化 → 发布目标”四步。任何阶段失败都不能更改旧目标。用 awk 数字运算计算百分比，`printf "%.2f"` 格式化；C locale 固定小数点。服务筛选只改变输出，不应跳过对输入其他行的校验。

扩展测试不要只验证“新文件存在”，还要准备一个旧报表，注入坏行/模拟 sort 失败后逐字节确认旧文件没变。零输入和无匹配输出表头是协议的一部分，应单独验收。

### P02 · 备份管家

先验证目录关系与名字，再持有覆盖整个备份周期的锁。使用独有临时归档；tar 成功后校验再发布。元数据与归档若需要“一起成功”，要么共同放在一个新目录中最后发布目录，要么在清单中使用明确的完成标记，不能让半份元数据看起来像成功备份。

恢复验证在新临时目录中进行，使用已知样本清单比对内容，保留原始样本不动。保留策略从只读计划开始，只识别自己的完成产物，不删除临时文件、未知文件或当前正在构建的备份。日志中记录失败阶段比只写“backup failed”更易排查。

### P03 · 批处理器

先给输入编号，再启动有上限的任务；不能拿任务文本作为文件名，因为重复项、斜杠和特殊字符会冲突。每项独立记录尝试次数、最终状态和结果，主进程回收后按编号合并。子任务日志与最终报告分开，避免并发输出污染结构。

生命周期由主进程负责：停止接收/启动新任务 → 向正在执行的直接子进程通知 TERM → wait → 写明中断状态 → 清理临时资源。若用“重试包装器再启动 worker”的多层结构，E15 仅管理直接子进程就不再足够；必须给包装器补上转发和回收协议，或让每个直接 worker 自己实现重试且不再留存无人管理的后代。不要直接拼接三个脚本就假定生命周期自然闭合。

先让成功、失败、空输入、重复项、中断五条路径可解释，再考虑动态补位和进度条。需要处理任意进程树或复杂取消时，用更适合的任务执行框架。
