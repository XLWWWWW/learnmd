# 06 · 工作检查表与速查

## 从临时命令到可维护脚本

- [ ] shebang、最低 Bash 版本、所需工具明确；不是“我在 zsh 中试过就算通过”。
- [ ] usage 说明参数、默认值、stdout 格式、stderr 和退出码。
- [ ] 用户输入在使用前校验；数值先限制字符、长度与范围。
- [ ] 每个值按参数传递，普通变量展开加引号；命令参数用数组或 `"$@"`。
- [ ] 固定 printf 格式；grep 字面值与正则用途明确；没有 eval 数据或 source 数据配置。
- [ ] 文件名中的空格、换行、前导 -、点文件、符号链接都有明确策略。
- [ ] 相对路径基准明确；不依赖启动时的 cwd、交互 alias 或用户终端 PATH。
- [ ] stdout 只输出业务结果；诊断使用 stderr；机器格式不会混入颜色或调试日志。
- [ ] 每个关键外部命令检查状态；grep 1 等预期非零没有被当成操作故障。
- [ ] 管道各阶段失败处理明确；复制 PIPESTATUS 前不插入其他命令。
- [ ] 了解 set -e 的条件例外，没有把它当完整异常系统。
- [ ] 临时文件由 mktemp 创建、权限合适；清理只处理自己成功取得的资源。
- [ ] 文件生成失败时不发布，旧文件不被提前截断；并发写者有协调方案。
- [ ] 所有启动的子任务都有回收责任；并发上限、失败汇总、信号处理明确。
- [ ] 锁失败不删除别人的锁；SIGKILL 后遗留资源有恢复流程。
- [ ] 重试有上限，考虑幂等和单次/总超时；失败尝试的部分输出不会伪装成成功产物。
- [ ] cron/CI 环境用同一套测试验收；在实际目标系统验证 GNU/BSD 与 Bash 版本差异。
- [ ] 日志与执行轨迹不暴露口令；没有把含秘密的命令长期 `set -x`。

## 常用写法速查

| 目的 | 写法 | 限制 |
|---|---|---|
| 打印字符串 | `printf '%s\n' "$value"` | 格式串固定 |
| 输出诊断 | `printf 'failed\n' >&2` | 不污染 stdout |
| 参数透传 | `command "$@"` | 不写成 `$*` |
| 数组透传 | `command "${args[@]}"` | Bash 特性 |
| 空值默认 | `${value:-default}` | 未设置与空串都回退 |
| 只处理未设置 | `${value-default}` | 空串会保留 |
| 文件存在 | `[ -e "$file" ]` | 断链可能返回假；另用 -L |
| 文件为符号链接 | `[ -L "$file" ]` | 尾斜杠会影响路径解析 |
| 原样读行 | `IFS= read -r line` | 无末尾换行需补条件 |
| 字面搜索 | `grep -F -e "$needle" < "$file"` | 1 表示无匹配 |
| NUL 清单 | `find ./root -type f -print0` | 不放进 Shell 变量 |
| 错误码 | `if command; then ...; else rc=$?; ...; fi` | else 第一时间保存 |
| 管道状态 | `states=("${PIPESTATUS[@]}")` | 紧跟管道，Bash 特性 |
| 临时目录 | `mktemp -d "${TMPDIR:-/tmp}/task.XXXXXX"` | 检查创建成功再清理 |
| 后台任务 | `command &` 后 `pid=$!` | 启动不等于成功 |
| 等待任务 | `wait "$pid"` | 检查每项状态 |
| 语法检查 | `bash -n script.sh` | 不执行，不检查业务正确性 |
| 执行追踪 | `bash -x script.sh` | 会显示展开值，注意秘密 |

## 常见症状与排查方向

| 症状 | 先检查 |
|---|---|
| 有空格的路径报“文件不存在” | 参数展开是否被拆分；实际收到多少参数 |
| 文件被意外清空 | 是否对输入同名文件使用 `>`；重定向是否提前发生 |
| 循环结束计数还是 0 | while 是否位于默认 Bash 管道子 Shell 中 |
| 文件最后一项漏处理 | 最后一行是否没有换行；read 条件是否完整 |
| grep 没查到就整个任务失败 | 是否把状态 1 与操作错误混同 |
| 前一个命令失败，脚本却报成功 | 管道末段、local 赋值、函数最后状态是否掩盖错误 |
| TERM 后仍有任务在跑 | 是否只停止包装 Shell，没有转发并回收子进程 |
| 每分钟任务偶尔运行两份 | 是否检查后再创建锁；锁是否过早释放 |
| 在终端成功，CI 失败 | Bash 版本、PATH、cwd、locale、权限和交互输入 |
| Mac 正常 Linux 异常或反过来 | 外部工具实现与扩展选项，不只是 Shell 版本 |

## 给真实脚本补的最小测试集合

1. 一个正常输入、一个空输入、一个缺失必填参数。
2. 路径/参数中的空格、空串、星号、前导 `-`；文件名协议还包括换行。
3. 文件缺失、父目录缺失、依赖命令失败。
4. 预期非零（例如 grep 无匹配）与真实故障分别验证。
5. 结果文件已存在时失败应保持旧数据；正常重跑是否幂等。
6. 有临时资源/锁/后台任务时，补正常完成、失败、TERM、争用路径。
7. 在实际运行平台检查工具和版本，不用“在我的电脑上成功”代替部署验收。

本工程测试用临时目录和短超时隔离练习；会故意模拟 cat、tar、grep、sort 失败。通过测试后，再补你真实场景的业务不变量，比如“只备份指定目录”“绝不修改输入”“重复执行不产生重复订单”。

## 学习进度自评

| 级别 | 你应当能独立做到 |
|---|---|
| 入门 | 解释参数边界，正确读行、分支、循环和默认值；完成 E01～E05 |
| 日常可用 | 处理日志、文件名、配置与 CLI；完成 E06～E09/E16 |
| 可靠工具 | 解释失败不破坏旧数据、有限重试与资源清理；完成 E10～E14 |
| 能维护团队脚本 | 证明并发上限与回收责任，完成 E15 和至少一个综合项目 |

毕业自测：不看答案重写 E05、E10、E14、E16，给每题加一个反例测试，再把实现讲给一位同事听。能说清楚限制条件，和能写出成功路径同样重要。

## 进一步阅读

- [GNU Bash Reference Manual](https://www.gnu.org/software/bash/manual/bash.html)：语法、展开、状态与内建命令的原始定义。
- [Shell expansions](https://www.gnu.org/s/bash/manual/html_node/Shell-Expansions.html)：展开顺序。
- [The set builtin](https://www.gnu.org/s/bash/manual/html_node/The-Set-Builtin.html)：errexit、nounset、pipefail 的精确条件。
- [ShellCheck SC2086](https://www.shellcheck.net/wiki/SC2086)：参数引用的常见错误。
- 本地 `help read`、`help trap`、`help wait`、`help getopts`：直接查看当前 Bash 所支持的接口。外部工具可用 `man find`、`man tar`、`man date` 对照当前系统，而不是直接套用另一系统的命令选项。
