# Go 反射练习题册

先尝试，再运行，再解释原因。每题至少写下：输入协议、可能 panic 的位置、你采用的判断依据。

Q01—Q12 是输出推演，Q13—Q18 是修复题，E01—E11 是有自动测试的实现题，E12 是性能实验，P01—P03 是综合项目，共 33 道主任务。Q 题答案与项目参考设计见 `03_提示与解析.md`；E 题完整代码见 `practice/solutions.go`。

## A. 输出推演：每题先不运行

这些代码段相互独立，默认已经导入所需标准库。局部变量写在函数内，类型的方法声明写在包级。每题不仅要写输出，还要说明哪些类型信息、寻址规则或接口规则导致这个结果。

### Q01：定义类型与类型别名 ★

```go
type UserID int64
type Alias = int64
fmt.Println(reflect.TypeOf(UserID(1)) == reflect.TypeOf(int64(1)))
fmt.Println(reflect.TypeOf(Alias(1)) == reflect.TypeOf(int64(1)))
fmt.Println(reflect.TypeOf(UserID(1)).Kind())
```

追加：为什么用 Kind 分组做整数解析可行，却不能只比较 Kind 就执行 `Set`？

### Q02：接口的静态类型与动态类型 ★

```go

```

### Q03：三个 Value，哪一个可以修改原值 ★

追加：把 `c.SetInt` 改成 `a.SetInt` 或 `b.SetInt`，分别会怎样？

### Q04：未导出字段的三个能力 ★★

### Q05：接口 nil 与带类型的 nil ★

## B. 修复题：写出最小反例，再修复

### Q13：危险的 nil 工具 ★

```go
func Empty(x any) bool {
    return reflect.ValueOf(x).IsNil()
}
```

要求：找出至少三种有代表性的输入，使其 panic 或暴露语义问题；重命名函数，使名字准确反映协议；修复后写出 nil、0、空 slice 的预期结果。不要把“nil”“零值”“长度为零”默认为同一个概念。

### Q14：字段导出器 ★★

```go
func Dump(x any) map[string]any {
    v := reflect.ValueOf(x)
    result := map[string]any{}
    for i := 0; i < v.NumField(); i++ {
        name := v.Type().Field(i).Tag.Get("json")
        result[name] = v.Field(i).Interface()
    }
    return result
}
```

要求：至少找出六个问题；覆盖指针、nil、未导出字段、未声明标签、`json:"-"`、含选项标签和重名；明确自己的映射协议后修复。你不需要完整复刻标准 JSON 的所有规则。

### Q15：小整数写入 ★★

```go
var n int8
v := reflect.ValueOf(&n).Elem()
v.SetInt(128)
fmt.Println(n)
```

要求：预测输出；设计一个拒绝越界写入的函数；验证 -129、-128、127、128 四个边界。错误输入不得修改原值。

### Q16：修改 map 中的结构体 ★★

```go
type User struct{ Name string }
m := map[string]User{"u1": {Name: "before"}}
v := reflect.ValueOf(m).MapIndex(reflect.ValueOf("u1"))
v.FieldByName("Name").SetString("after")
```

要求：解释为什么失败；分别给出“复制结构体、改完写回”与“map 保存指针”两种方案，说明 nil 指针、缺失键和并发修改分别要如何处理。

### Q17：缓存了谁的字段 ★★★

某组件以 `reflect.Type` 为键，缓存第一次请求中 `reflect.ValueOf(&user).Elem().FieldByName("Name")`，下一次同类型请求直接复用该 Value。

要求：解释为什么第二个用户可能没有被更新；指出并发请求和对象生命周期问题；给出正确缓存内容及同步策略；说明为什么给错误缓存加锁仍不能修复对象绑定问题。

### Q18：用 recover 校验动态调用 ★★★

```go
func Call(fn any, args ...any) (out []reflect.Value, err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("bad arguments: %v", r)
        }
    }()
    in := make([]reflect.Value, len(args))
    for i, arg := range args {
        in[i] = reflect.ValueOf(arg)
    }
    return reflect.ValueOf(fn).Call(in), nil
}
```

要求：构造 typed nil 函数、数量错误、类型错误、nil 参数和业务 panic 五类输入；给出明确的错误分类；说明为何业务函数里的 panic 不能一概归因于参数错误。参考 E08 实现输入检查，保留业务 panic 的传播。

## C. 编程题：在 `practice/exercises.go` 中实现

公共约定：只使用标准库；返回错误描述可以自行设计，测试不要求照抄参考文字；除 E08 明确传播业务 panic 外，题目列出的错误输入应返回 error。除特别注明，结构体只处理直接声明的字段，不展开嵌入或嵌套字段。

### E01：Inspect ★

```go
func Inspect(x any) (reflect.Type, reflect.Kind)
```

返回动态类型与 Kind。nil 接口返回 `nil, reflect.Invalid`；typed nil 指针保留指针类型。必须识别定义类型与底层 Kind 的差异。

运行：`go test ./practice -run '^TestE01' -v`。

### E02：IsNilLike ★

```go
func IsNilLike(x any) bool
```

nil 接口返回 true；Channel、Func、Interface、Map、Pointer、Slice 的 nil 值返回 true。其余值返回 false，包括 0、false、空字符串、非 nil 空 map / slice。这是本题约定的普通 nil 判断，不处理 unsafe.Pointer。

### E03：Fields ★★

```go
func Fields(x any) ([]FieldInfo, error)
```

接收 struct 或非 nil 的 `*struct`。按声明顺序返回直接声明的导出字段；每个结果包含 Name、Index、Type、原始 json 标签值和标签存在标记。未导出字段跳过；嵌入字段只作为一个直接字段返回。nil、typed nil、非 struct、多层指针返回 error。

### E04：SetField ★★

```go
func SetField(dst any, name string, src any) error
```

目标必须是非 nil 的 `*struct`。只设置直接声明、已导出、可设置的同名字段。使用 AssignableTo 规则，不做隐式转换；int 不能自动写入定义类型 Count。

无类型 nil 允许清空六类常见可为 nil 的目标；nil 写入 string / int 等返回 error。具体值可赋给其实现的接口，例如 `*bytes.Buffer` 赋给 `io.Writer`。失败时目标不变；提升字段名不在本题范围内。

### E05：ToMap ★★

```go
func ToMap(x any) (map[string]any, error)
```

输入协议同 E03。忽略未导出字段，按自定义 `map` 标签生成浅层 map：

- 没标签或标签名为空：使用 Go 字段名。
- `map:"user_id"`：重命名。
- `map:"-"`：跳过字段。
- `map:",omitempty"`：字段 IsZero 时省略。
- 未知选项和重复输出键返回 error。即使重复字段会被 omitempty 省略，也必须报 schema 冲突。

保留嵌套对象原值；不递归、不深拷贝。非 nil 空 slice 不会因本题的 omitempty 被省略。请先解释这个约定与标准 JSON 的区别。

### E06：ApplyDefaults ★★

```go
func ApplyDefaults(dst any) error
```

目标同 E04。只处理带 `default` 标签、导出且当前 IsZero 的字段；非零值保持原样，不解析其 default。支持 string、bool 和所有有符号整数，包括相应 Kind 的定义类型。使用十进制解析整数、`strconv.ParseBool` 解析 bool；不展开指针或嵌套 struct。

非法字面量、溢出、不支持的待填充类型均返回 error。**整次调用失败时所有字段保持原值**，因此先解析再提交。没有标签与 `default:""` 用 Lookup 区分。

追加：为什么这个协议无法保留“用户有意填 false”？如何在生产配置模型里表达来源？

### E07：Validate ★★

```go
func Validate(x any) ([]Violation, error)
```

输入同 E03，只读。解析 `validate:"required,min=2"`：

- required 使用 Go 的 IsZero 语义，支持任意有效字段类型。
- min=N 支持 string 和有符号整数，包括定义类型。字符串按 Unicode rune 数量计算，N 必须非负；整数按数值比较，允许负阈值。
- 规则按标签顺序执行，字段按声明顺序检查；收集全部业务违规，每个包含 Field、Rule。
- 未导出字段、无标签或空标签跳过；未知规则、格式错误和不支持的 Kind 返回 error；此时不返回半份违规列表。

追加：rune 数是否等同用户感知的字符数量？required 对 bool、非 nil 空 slice 的结果是否符合你正在做的产品？

### E08：Invoke ★★★

```go
func Invoke(fn any, args ...any) ([]any, error)
```

只接受固定参数个数的非 nil 函数。检查参数数量，每个参数按 E04 的严格赋值与 nil 协议处理。拒绝变参函数；正常返回值保持原顺序。

返回的 error 表示调用器输入错误；业务函数返回的 error 是结果切片中的一个元素。业务 panic 原样传播。支持没有返回值的函数、接口参数和可为 nil 的参数。

追加：若支持变参，Call 与 CallSlice 两种输入协议应该怎样设计？不要悄悄猜测调用者是否希望展开 slice。

### E09：IncrementMap ★★★

```go
func IncrementMap(m any, key string, delta int64) error
```

接收非 nil map；键的 Kind 必须是 String，元素 Kind 必须为有符号整数，支持定义类型。找到 key 的计数并加 delta；缺失键按 0 处理，再写回 map。无需传 map 指针。

必须检查 int64 加法本身是否溢出，再检查结果是否能放入实际元素类型；任意错误都不得修改 map。拒绝 nil map、非 map、无符号整数值、非字符串键。不承诺并发写安全。

### E10：FieldCache.Metadata ★★★

```go
func (c *FieldCache) Metadata(t reflect.Type) ([]FieldInfo, error)
```

零值 FieldCache 可以使用，使用后不要复制。接收 struct / `*struct` 类型；把一层指针规范化到 struct，nil Type、多层指针和其他类型返回 error。

元数据内容同 E03，以 reflect.Type 为键并发安全缓存。调用者修改返回的切片不得污染缓存；不得缓存任何特定对象的 reflect.Value。正确性不要求所有并发调用只构建一次，允许并发构建后用 LoadOrStore 统一保存。

运行并发验证：`go test ./practice -run '^TestE10' -race -v`。

### E11：ScanRow，模拟行映射 ★★★

```go
func ScanRow(dst any, columns []string, values []any) error
```

目标同 E04。直接导出字段通过 db 标签匹配列名，没标签或空标签使用字段名，`db:"-"` 跳过。列顺序可不同于字段顺序；没有出现在 columns 的字段保持原值。

要求：列和值数量一致；未知列、重复输入列、重复可映射 db 名、不可赋值的值都返回 error。源值无类型 nil 只能赋给可为 nil 的目标；类型严格匹配，不自动把 int 转成 int64。**先完成整行检查，再统一写入**。

本题只接收模拟数据，不连接数据库，不实现 Scanner、数字字符串解析或驱动内存管理。

## D. 综合项目：选一个完成，再做下一个

这些项目提供明确验收目标和参考设计，不包含自动测试或完整答案代码。建议每个项目自行补不少于 8 个有意义的边界用例。

### P01：审计对象导出器 ★★★

实现 `AuditView(x any, maxDepth int) (map[string]any, error)`。

范围：输入 struct 或非 nil 的 `*struct`；只导出带 audit 标签的导出字段，默认白名单。支持基本标量、嵌套 struct、`*struct`，以及元素是 struct / `*struct` 的 slice。对于需要实际导出的字段，其他类型明确报错，不默默字符串化；已跳过或整体脱敏的字段不必深入其类型和值。

协议：`audit:"name"` 重命名，`audit:"email,redact"` 输出 `"***"`，`audit:"-"` 跳过；空名字用字段名；未知选项、同层输出名冲突报错。nil 嵌套指针输出 nil。根深度为 0，每进入嵌套对象加 1；maxDepth 必须非负，超过时返回含字段路径的 error。

验收：正确识别祖先路径上的指针循环；同一对象被两条独立路径引用不能误判为循环；不能修改输入；不能返回别人的可变缓存切片；未标记字段即使导出也不会出现在结果里。

### P02：请求参数绑定器 ★★★

实现 `Bind(dst any, params url.Values) error`，目标是非 nil 的 `*struct` DTO。

范围：只有带 `form` 标签的直接导出字段可写；`form:"-"` 不可写；空标签名用字段名。支持 string、bool、有符号整数、相应指针、`[]string`；另支持实现 `encoding.TextUnmarshaler` 的显式自定义类型。自定义解码器在新分配的临时值上执行。

协议：缺失 key 保留原值；提供了空字符串按目标类型实际解析；scalar 收到多个值报错；`[]string` 接收全部值并复制输入；未知 key、重复 form 名和解析失败都报错。传入的已存在指针所指向的对象不得被临时解析修改。

验收：支持显式 false / 0；整数无损；批量失败不修改原对象及其已有指针对象；错误包含参数名与原因；只用类型元数据缓存；加入并发缓存测试和完整绑定 benchmark。

### P03：动态处理器注册表 ★★★

实现 `Register(name string, fn any) error` 与 `Dispatch(ctx context.Context, name string, payload []byte) ([]byte, error)`。

只接受签名 `func(context.Context, T) (R, error)`：T、R 必须是 struct，第二个返回值必须恰好是 error 接口类型，不接受任意恰好实现 error 的具体返回类型。拒绝变参、nil 函数、重复名称和错误签名。

Dispatch 查找注册项，创建 T，以标准 JSON 解码并调用，成功时编码 R；未知名称、无效 JSON、nil context、已取消 context、业务 error 均有可区分结果。业务 panic 按本项目约定继续传播；反射本身不会自动停止一个不检查 context 的业务函数。

验收：注册阶段完成签名分析；可并发 Register / Dispatch；持锁查表后释放锁再调用业务代码；每次请求创建独立对象；不会把 nil error 与带类型的 nil error 混淆；与直接函数调用建立端到端对照 benchmark。
