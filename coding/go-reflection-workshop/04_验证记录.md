## 性能样本

完成其他编译检查后，单独运行以下命令；表格采用这组结果，未采用并行编译时较不稳定的初次测量：

```sh
sh run.sh test -tags solution ./practice -run '^$' -bench E12 -benchmem -benchtime=300ms -count=3
```

| 测量项 | 三次 ns/op | 中位数 ns/op | B/op | allocs/op |
|---|---|---:|---:|---:|
| Direct | 0.2367 / 0.2388 / 0.2347 | 0.2367 | 0 | 0 |
| ReflectByName | 19.97 / 21.24 / 20.67 | 20.67 | 0 | 0 |
| ReflectByIndex | 2.286 / 2.125 / 2.273 | 2.273 | 0 | 0 |
| Uncached metadata | 166.8 / 160.8 / 161.7 | 161.7 | 256 | 1 |
| CachedWithDefensiveCopy | 36.86 / 38.98 / 40.76 | 38.98 | 256 | 1 |

可以从本次样本观察到：按下标读取减少了名字查找成本；缓存元数据减少重复字段和标签处理，但返回切片的复制仍有分配。反射读取在这里没有发生分配，因此不应把“反射一定产生分配”当成规则。

Direct 的亚纳秒结果是经过优化后的循环平均成本，不是函数调用延迟。这个微基准不包含真实 HTTP、数据库、JSON 全流程，也不能直接推导业务吞吐量或对其他 Go 版本的固定性能倍数。
